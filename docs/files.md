# Файлы приложения

`tnt-files` — диски приложения: у диска имя, драйвер и один договор
на всех драйверах — положить, взять, потоком, есть ли, удалить, копия,
перенос, размер, публичный адрес и ссылка со сроком. Драйвера два:
`local` — каталог узла через [`tnt-fs`](https://github.com/tnt-skein/tnt-fs),
`s3` — ведро через клиент [`tnt-s3`](https://github.com/tnt-skein/tnt-s3).

```lua
local files = require('tnt.files')

local store = files.new({
    default = 'local',
    disks = {
        ['local'] = { driver = 'local', root = '/var/lib/app/storage', url = '/storage' },
        uploads = { driver = 's3', client = bucket, prefix = 'uploads/', url = 'https://cdn.example.org/uploads' },
    },
})

store:disk('uploads'):put('avatars/7.png', png, { type = 'image/png' })   --> true
store:disk():get('avatars/8.png')          --> nil, диск local: файл avatars/8.png не прочитан: файла нет
```

Отказ — пара `nil, err` с родом, одним на все драйверы: `missing`,
`denied`, `full`, `unavailable`, `failed`. Исключение — ошибка
программиста: негодная настройка, незнакомый диск, негодный путь.

Зависит от [`tnt-must`](https://github.com/tnt-skein/tnt-must) (проверки
аргументов и настроек) и [`tnt-fs`](https://github.com/tnt-skein/tnt-fs)
(драйвер `local` и договор чтения и записи кусками). От `tnt-s3` пакет
не зависит: клиент ведра приходит настройкой диска `client`.

## Зачем пакет

Файлы узла и объекты в ведре — два разных предмета. У `tnt-fs` отказ
с родом `missing` и кодом `errno`, у `tnt-s3` — `TntStorageFailure`
с кодом ответа, а «нет объекта» у `get` — вовсе `nil` без отказа.
Каталоги у файлов есть, у ведра нет. Файл пишется во временный рядом
и переименовывается, объект уходит одним PUT или частями. Код, который
кладёт загрузку посетителя, при таком раскладе знает, куда она ляжет,
и переезд с каталога на ведро — правка каждого места, где решают
по отказу.

Здесь место выбирает настройка, а код одинаков:

1. **Один договор.** Десять действий диска ведут себя одинаково
   на обоих драйверах: «файла нет» — отказ `missing` у всех, кому файл
   нужен; удаление того, чего нет, — удача; промежуточные каталоги
   локальный диск заводит сам; каталог по пути — не файл.
2. **Один род отказа.** Драйвер переводит свой отказ в род диска,
   а свой оставляет в `err.cause` — тому, кому рода мало.
3. **Поток на обоих драйверах.** Файл в сотни мегабайт читается
   и пишется кусками: у каталога — пулом нитей `fio`, у ведра —
   запросами с диапазоном и загрузкой частями. В памяти узла лежит
   один кусок, сколько бы ни весил файл.
4. **Адрес файла.** Публичный — из настройки диска, ссылка со сроком —
   подписью ведра либо роутера, который раздаёт файлы каталога.

## Как пользоваться

Примеры этого документа прогнаны на каталоге `/tmp` и на Garage стенда
(`make s3-up`); вывод — как напечатал прогон.

### Диски: `files.new` и `store:disk`

```lua
local store = files.new({
    default = 'local',
    disks = {
        ['local'] = { driver = 'local', root = '/tmp/tnt-files-doc', url = '/storage' },
        uploads = { driver = 's3', client = bucket, prefix = 'uploads/',
            url = 'http://127.0.0.1:19000/tnt-live/uploads' },
    },
})

store:disk()              -- диск по умолчанию: local
store:disk('uploads')     -- диск по имени
store:disk('media')
--> бросок: диска «media» нет: есть local, uploads
```

`files.new` в сеть и на диск не ходит: каталог локального диска заведёт
первая запись, ведро спросит первый вызов. Диск один — он и по умолчанию,
`default` тогда не нужен; дисков несколько — `default` обязателен.

| Настройка диска | Драйвер | Что |
|---|---|---|
| `driver` | оба | `local` либо `s3` |
| `root` | `local` | каталог диска; «/» на конце снимается |
| `sign` | `local` | функция `sign(path, expires)` — подпись ссылки со сроком (ниже) |
| `client` | `s3` | клиент `tnt-s3`: ведро, ключи, срок, повторы — его настройки |
| `prefix` | `s3` | приставка ключей: пусто либо отрезки с «/» на конце; одно ведро служит многим дискам |
| `url` | оба | публичный адрес, под которым видны пути диска: `http(s)://узел/путь` либо `/путь` |

Незнакомый ключ, чужой драйверу ключ, негодный адрес или приставка —
исключение на строке того, кто завёл файлы: диски заводят при подъёме
узла, а первый файл кладут через час.

```lua
files.new({ disks = { a = { driver = 'local', root = root }, b = { driver = 'local', root = root } } })
--> бросок: настройки файлов.default — имя диска по умолчанию: дисков несколько (a, b)
files.new({ disks = { a = { driver = 'ftp' } } })
--> бросок: настройки файлов.disks.a.driver — одно из «local», «s3», а не «ftp»
```

### Что умеет диск

| Вызов | Что отдаёт |
|---|---|
| `put(path, content, opts)` | `true`; `content` — строка либо читатель кусками |
| `get(path)` | содержимое строкой |
| `stream(path)` | читатель кусками |
| `writer(path, opts)` | писатель кусками: файл встаёт на место в `finish` |
| `exists(path)` | `true` либо `false`; каталог по пути — `false` |
| `delete(path)` | `true`; файла не было — тоже `true` |
| `copy(from, to)` | `true`; место копии занято — копия ложится поверх; на то же место — только проверка, есть ли файл |
| `move(from, to)` | `true`; место занято — файл ложится поверх; на то же место — как у `copy` |
| `size(path)` | размер в байтах |
| `url(path)` | публичный адрес; в сеть не ходит |
| `temporary_url(path, expires)` | ссылка на `expires` секунд, от 1 до 604800 (семь суток) |
| `name`, `driver` | имя диска и драйвер |

`opts` у `put` и `writer` — `{ type }`, вид содержимого: ведро хранит его
и отдаёт по адресу, у локального диска вида нет — его называет тот,
кто файл раздаёт.

```lua
local disk = store:disk('uploads')

disk:put('avatars/7.png', 'картинка', { type = 'image/png' })   --> true
disk:get('avatars/7.png')                                        --> картинка
disk:exists('avatars/7.png'), disk:exists('avatars/8.png')       --> true, false
disk:size('avatars/7.png')                                       --> 16
disk:copy('avatars/7.png', 'avatars/7-old.png')                  --> true
disk:move('avatars/7-old.png', 'trash/7.png')                    --> true
disk:delete('trash/7.png'), disk:delete('trash/7.png')           --> true, true
disk:url('avatars/7.png')              --> http://127.0.0.1:19000/tnt-live/uploads/avatars/7.png
```

С диском `local` те же строки отвечают тем же; `url` —
`/storage/avatars/7.png`.

### Путь

Путь — отрезки через «/»: без ведущей и конечной «/», без пустых
отрезков, `.`, `..` и управляющих знаков, не длиннее 1024 байт (столько
берёт ключ S3). Негодный путь — исключение, а не отказ:

```lua
disk:get('../etc/passwd')
--> бросок: путь — отрезки через «/» без пустых, «.», «..» и управляющих знаков, а не «../etc/passwd»
```

Путь из имени, присланного посетителем, проходит через безопасное имя —
`file.name` у присланного файла роутера
([`tnt-router`](https://github.com/tnt-skein/tnt-router/blob/main/docs/router.md),
«Присланный файл»), — а шаг вверх, дошедший до диска, — ошибка кода.
Проверка одна на оба драйвера: у каталога `..` увёл бы запись за корень,
а у ведра libcurl свернул бы путь, и запрос ушёл бы в чужой объект.

### Отказ

`err` — таблица, которая читается и как строка:

```lua
local _, err = store:disk():get('avatars/8.png')

err.kind     --> 'missing'
err.disk     --> 'local'
err.path     --> 'avatars/8.png'
err.cause    --> nil: у «файла нет» отказа драйвера нет
tostring(err)                  --> диск local: файл avatars/8.png не прочитан: файла нет
json.encode({ err = err })     --> {"err":"диск local: файл avatars/8.png не прочитан: файла нет"}
```

| Род | Когда | `local` (`tnt-fs`) | `s3` (`tnt-s3`) |
|---|---|---|---|
| `missing` | файла нет | `missing`; каталог по пути | промах `get`, `head`, `reader`; `NoSuchKey` у копии |
| `denied` | нет прав | `denied` | `denied`: 401, 403, неверная подпись |
| `full` | кончилось место | `full` | — |
| `unavailable` | хранилище сейчас не отвечает: время это лечит | — | `unreachable`, `busy`, `timeout`, `broken`, `closed` |
| `failed` | всё прочее | `exists`, `failed` | `rejected`, `conflict` (объект подменён посреди чтения), `overflow` |

Роды названы и константами фасада — `files.MISSING`, `files.DENIED`,
`files.FULL`, `files.UNAVAILABLE`, `files.FAILED`, — а `files.is_failure`
отличает отказ диска от прочего: скажем, от отказа источника у `put`
с читателем, который приходит как есть (ниже, «Поток»).

```lua
err.kind == files.MISSING                 --> true
files.is_failure(err)                     --> true
files.is_failure({ kind = 'missing' })    --> false: похожая таблица — не отказ диска
```

Отказ драйвера как есть лежит в `err.cause`: у файла — отказ `tnt-fs`
с `errno`, у ведра — `TntStorageFailure` с `server_code`. Причина
в тексте — словами драйвера: у файла с кодом — слова системы, у ведра —
текст отказа `tnt-s3`. «Нет прав» на обоих драйверах выглядит так:

```lua
readonly_bucket:put('x.txt', 'y')
--> nil, диск ro: файл x.txt не записан: PUT 127.0.0.1:19000/tnt-live/x.txt: 403 AccessDenied:
--      Forbidden: Operation is not allowed for this key.       (kind = denied)
readonly_directory:put('x.txt', 'y')
--> nil, диск local: файл x.txt не записан: Permission denied   (kind = denied)
```

### Поток: `stream`, `writer` и `put` с читателем

Читатель и писатель — по договору
[`tnt-fs`](https://github.com/tnt-skein/tnt-fs/blob/main/docs/fs.md)
(«Чтение и запись кусками»), и все три стороны его понимают: файл, ведро
и диск.

- **Читатель** — `read()` отдаёт кусок (непустую строку), `nil` без
  отказа в конце и `nil, err` при отказе; `close()` закрывает. Читать
  после конца можно — вернётся то же, чем чтение кончилось; после
  `close` — исключение.
- **Писатель** — `write(кусок)`, `finish()` ставит файл на место целиком,
  `abort()` бросает запись, и файла нет. Отказ записи кончает её:
  черновик уже убран, и дальше писатель отвечает тем же отказом. Запись
  после `finish` и `abort` — исключение.

```lua
local reader = disk:stream('avatars/7.png')
reader:read(), reader:read()                          --> картинка, nil

local writer = disk:writer('exports/2026-09.csv', { type = 'text/csv' })
writer:write('id;сумма\n')
writer:write('1;100\n')
writer:finish()                                       --> true
disk:get('exports/2026-09.csv')                       --> id;сумма\n1;100\n

disk:put('exports/big.csv', fs.reader('/tmp/big.csv'))   --> true, кусками
disk:size('exports/big.csv')                             --> 13000
store:disk('local'):put('copy.csv', disk:stream('exports/big.csv'))   --> true: из ведра в каталог
```

`put` с читателем читает его до конца и закрывает. Присланный файл
роутера (`request.files.avatar`) — не читатель: его `read()` отдаёт файл
целиком на каждый вызов, и переливание не кончилось бы, — такой `put`
бросает. Файл во временном файле кладут читателем `fs.reader(file.path)`,
файл в памяти — строкой `file:read()`. Отказ чтения
источника приходит **как есть**, а не родом диска: это отказ того, кто
источник дал, — файла, другого диска, чужого читателя. Файл при этом
не ложится.

Читатель и писатель — одного файбера: `fio` и клиент HTTP уступают
на каждом куске, и два файбера, читающие один читатель, делили бы
куски как придётся.

Что держит узел за поток в 50 МБ — куча Lua после сборки мусора сверх
начала потока; мерит так же живая проверка `files_live_test.lua`,
и её порог — половина файла:

| Драйвер | Запись | Чтение | Кусок |
|---|---|---|---|
| `local` | 0,1–0,2 МБ | 0,1–0,2 МБ | 64 КБ читателя `tnt-fs` |
| `s3` | 8,5 МБ | 7,0 МБ | часть загрузки и кусок чтения по 8 МБ |

### Публичный адрес и ссылка со сроком

`url(path)` — адрес диска из настройки `url` и путь, каждый отрезок
закодирован по RFC 3986. В сеть не ходит и не проверяет, есть ли файл.
Без настройки `url` — исключение: «у диска local нет публичного адреса —
настройка url». Адрес, которого нет, — промах того, кто настраивал диск,
и заметить его надо на первом вызове, а не в разосланном письме.

`temporary_url(path, expires)` — ссылка, по которой файл заберёт тот,
у кого прав нет, пока идут `expires` секунд. Срок — от секунды до семи
суток: дольше ведро не подписывает, а договор у дисков один.

- **Ведро** подписывает ссылку само (`presign` клиента `tnt-s3`):
  по ней файл отдаёт служба S3, узел в раздаче не участвует.
- **Локальный диск** — функцией `sign(path, expires)` из настроек:
  ссылку подписывает тот, кто файл раздаёт, — обычно роутер
  (`signed_url`,
  [`tnt-router`](https://github.com/tnt-skein/tnt-router/blob/main/docs/router.md),
  «Подписанная ссылка»). Без
  `sign` — исключение: «у диска local нет подписи ссылок со сроком —
  настройка sign».

Раздача файлов локального диска по ссылке со сроком — маршрут роутера
со слоем `signed()` и ответом по кускам:

```lua
local web = router.new({ url = 'https://app.example.org', signing = { key = signing_key } })

web.get('/files/*path', function(request)
    local reader, err = disk:stream(request.params.path)

    if reader == nil then
        return nil, { status = err.kind == 'missing' and 404 or 500, reason = tostring(err) }
    end

    -- Договор читателя совпадает с источником ответа по кускам: кусок,
    -- nil в конце, nil, err — обрыв.
    return router.stream(function()
        return reader:read()
    end, 200, { ['content-type'] = 'application/octet-stream' })
end, { name = 'files', middleware = { web.signed() } })

local store = files.new({
    disks = {
        ['local'] = {
            driver = 'local',
            root = '/var/lib/app/storage',
            sign = function(path, expires)
                return web.signed_url('files', { path = path }, { expires = expires, full = true })
            end,
        },
    },
})

store:disk():temporary_url('отчёты/сентябрь.pdf', 600)
--> https://app.example.org/files/%D0%BE%D1%82%D1%87%D1%91%D1%82%D1%8B/%D1%81%D0%B5%D0%BD%D1%82%D1%8F%D0%B1%D1%80%D1%8C.pdf
--      ?expires=1790387309&signature=fPM86KEwuUpE9bv56EcqdzFyKmaLblOrLvf0T_FTqZA
```

Живая проверка открывает обе ссылки, пока срок идёт, и через две
секунды после срока в одну секунду — уже нет: роутер отвечает 403
`router_signature_expired`, служба S3 — своим отказом (AWS — 403
«Request has expired», Garage — 400 «Date is too old»). Ответ `sign`
парой `nil, err` — отказ `failed` с текстом отказа подписи.

### Драйвер `local`

Путь диска приставляется к корню. Всё, что обещает `tnt-fs`, достаётся
диску как есть: запись атомарна (временный файл рядом и переименование)
и сбрасывается на диск, права нового файла — `0640`, ни одно действие
не держит узел. Сверх `tnt-fs`, ради одного договора с ведром:

- промежуточные каталоги под файлом заводятся сами, с правами по umask;
- каталог по пути — не файл: его «нет» у `get`, `stream`, `size`,
  `copy` и `move`, `exists` отвечает `false`, а `delete` — `true`
  и каталог не трогает;
- копия — читатель источника в писатель копии: в памяти один кусок,
  а копия встаёт на место целиком;
- перенос — переименование: в пределах тома атомарен и байтов
  не копирует.

### Драйвер `s3`

Путь диска — ключ объекта после приставки `prefix`. Клиент приходит
настройкой: его заводит приложение своими настройками ведра, ключей,
срока и повторов
([`tnt-s3`](https://github.com/tnt-skein/tnt-s3/blob/main/docs/s3.md)),
и одно ведро служит многим дискам —
у каждого своя приставка. Копия и перенос — силами службы, байты через
узел не идут; перенос — копия и удаление: переименования у S3 нет.
Чтение кусками — запросами с диапазоном, запись — загрузкой частями.

## Чем пришлось поступиться

- **Вид содержимого знает только ведро.** `type` у локального диска
  не хранится: вид называет тот, кто файл раздаёт, — по расширению или
  по записи рядом.
- **Каталог по пути — не файл, и удалить его нельзя.** `delete` каталога
  отвечает `true` и ничего не трогает: у ведра каталогов нет, и договор
  о них молчит. Пустые каталоги после удаления файлов остаются.
- **Путь — не длиннее 1024 байт, а отрезок у каталога — не длиннее
  255.** Первое — предел ключа S3, второе — файловой системы узла;
  длинный отрезок на локальном диске — отказ `failed`
  («File name too long»).
- **Перенос в ведре — две операции.** Копия удалась, удаление нет —
  файл лежит на обоих местах, и это отказ, а не удача.
- **Копия в ведре — не больше 5 ГБ**: одной копией служба больше
  не берёт, частями копия не делается.
- **Отказ источника у `put` — как есть.** Род диска у него был бы
  ложью: это отказ того, кто источник дал.
- **Ссылка со сроком у локального диска — дело приложения.** Пакет
  не раздаёт файлы сам: раздача — маршрут роутера, и подпись у неё
  роутерова, а не своя вторая.
- **Ссылку отозвать нельзя** — ни у ведра, ни у роутера: выдают её
  на короткий срок.

## Проверки

Проверки лежат в `test/` и идут на luatest. Локальный диск проверяется
на настоящем каталоге — у каждой проверки свой, — а ведро — настоящим
клиентом `tnt-s3` на двойнике libcurl: видно и то, что уходит службе,
и то, как её ответ становится отказом диска. Отказы, которых настоящий
каталог по заказу не даст, — нет прав, кончилось место, сбой посреди
потока, отказ `stat` — даёт подменённый `fio` под `tnt-fs`. Место броска
каждой ошибки программиста сверяется со строкой вызова в файле проверок.

- `files_test.lua` — настройки дисков и отказы о них, выбор диска,
  отказ строкой и в JSON, пути, адреса, ссылка без подписи и срок.
- `local_test.lua` — договор диска на настоящем каталоге: запись
  и чтение, «файла нет» у всех действий, каталог по пути, поток,
  писатель, `put` с читателем, отказы `denied`, `full`, `failed` через
  подменённый `fio`, копия и перенос, подпись ссылки.
- `s3_test.lua` — договор диска поверх настоящего клиента `tnt-s3`
  на двойнике libcurl: что уходит службе, приставка, роды по кодам
  ответа, копия и перенос службой, чтение по диапазону, запись,
  подписанная ссылка.
- `files_live_test.lua` — 4 проверки обоих драйверов против каталога
  и Garage в докере: 50 МБ потоком в обе стороны без роста памяти,
  ссылки со сроком до и после срока (у каталога ссылку подписывает
  и файл раздаёт настоящий роутер `tnt-router`), одни и те же роды
  «нет файла» и «нет прав», копия и перенос.

```sh
make s3-up         # Garage в докере: ведро tnt-live, ключ для записи и ключ только для чтения
make test          # проверки, живые — при поднятом Garage
make s3-down
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование всех модулей
```

Без поднятого Garage живые проверки пропускаются: гейты не зависят
от докера. Соседи проверок — клиент `tnt-s3`, роутер `tnt-router`
и чтение окружения `tnt-env` — ставит `make deps`; зависимостями пакета
они не объявлены.
